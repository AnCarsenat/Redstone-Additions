# Redstone Additions — Contributing Guidelines

!!! info "Addons, contributions and the licence"
    Writing an **addon** needs no permission: keep it in your own namespaces, include
    no `ra_*` namespace that ships with the pack, and publish it wherever you like.
    Sending a **contribution** here grants the maintainer the right to ship it as part
    of Redstone Additions. Redistributing the pack itself, in whole or in part, needs
    written permission. Full terms in the
    [licence](https://github.com/AnCarsenat/Redstone-Additions/blob/main/LICENSE).

**Minecraft:** 26.3 only (data pack format 121)  
**Source:** Kotlin in `redstone_additions/`, generated by [Kore](https://kore.ayfri.com)  
**Version:** `version` in `redstone_additions/gradle.properties` — see [Release and Versioning](release.md)

## Setting up

| Tool | Version |
| --- | --- |
| JDK | 25 (`jvmToolchain(25)` in `build.gradle.kts`) |
| Python | 3.10+, only for `tools/compare_reference.py` and the docs tools |

```bash
git clone https://github.com/AnCarsenat/Redstone-Additions.git
cd Redstone-Additions/redstone_additions
./gradlew koreBuild
```

The Gradle wrapper fetches Gradle, Kotlin and Kore. The pack lands in
`build/kore/redstone_additions/`. [Getting Started](getting-started.md) covers the build, strict
mode and the IDE in detail.

## Installing into a world

`koreRun` builds the pack and copies it into a world's `datapacks/` folder. **Which** world is
chosen with the `-Pworld` Gradle flag; without it, `koreRun` builds and installs nowhere.

| Command | Installs into |
| --- | --- |
| `./gradlew koreRun -Pworld="Redstone Test"` | the world named `Redstone Test` under `<minecraft dir>/saves/` |
| `./gradlew koreRun -Pworld="/path/to/saves/Redstone Test"` | that world folder (a value containing `/` or `\` is a path) |
| `./gradlew koreRun -Pworld="/path/to/saves/Redstone Test/datapacks"` | the same; a path ending in `datapacks` is used as-is |
| `./gradlew koreRun -Pworld` | `ra.world` from your `local.properties` (below) |
| `./gradlew koreRun` | nowhere — the pack is only built |

Add `--continuous` to rebuild and reinstall on every save:

```bash
./gradlew koreRun -Pworld --continuous
```

Then type `/reload` in game. `koreLink` copies (it still runs `koreBuild` first, which Gradle skips when nothing changed), and `koreClean` deletes
the output and removes the pack from every place it was copied to.

### `local.properties`

Your own world and Minecraft directory belong in `redstone_additions/local.properties`. The
file is git-ignored; copy the template once:

```bash
cp local.properties.example local.properties
```

```properties
# The world `./gradlew koreRun -Pworld` installs into when -Pworld has no value:
# a world name under <minecraft dir>/saves, or a full path to a world folder.
ra.world=Redstone Test

# Optional: a Minecraft directory other than the OS default (~/.minecraft, %APPDATA%\.minecraft),
# e.g. a Prism Launcher instance.
#ra.minecraftDir=/home/me/.local/share/PrismLauncher/instances/26.3/minecraft
```

| Key | Used when | Effect |
| --- | --- | --- |
| `ra.world` | `-Pworld` is given **without** a value | the target world, name or path |
| `ra.minecraftDir` | the target is a world **name** | where `saves/` is looked up — set it for a Prism / MultiMC / CurseForge instance |

A bare `-Pworld` with no `ra.world` stops the build with a message saying exactly that.
`./gradlew koreWorlds` lists the worlds the plugin can see in the Minecraft directory, which is
the quickest way to check `ra.minecraftDir`.

### Dedicated servers

A server with RCON enabled reloads on its own after `koreRun`: set `enable-rcon=true`,
`rcon.port` and `rcon.password` in `server.properties`, and export `RCON_PASSWORD` before running
Gradle. Point `-Pworld` at the server's world folder by path. Without a password the reload is
skipped with a warning, not a failure. See Kore's
[Gradle plugin](https://kore.ayfri.com/docs/guides/gradle-plugin) page for the `rcon { }` options.

!!! warning "Never load the old beet build and the Kore build together"
    Both write the same namespaces. With both enabled every function exists twice, the pack
    that loads last wins file by file, and `ra:tick` is scheduled by both. Remove
    `redstone_additions_data_pack` (or any release zip older than the Kore build) from the
    world's `datapacks/` before the first `koreRun`.

## The development loop

1. Edit Kotlin under `redstone_additions/src/main/kotlin/ra/`.
2. `./gradlew koreRun -Pworld --continuous` keeps the world in sync.
3. `/reload` in game and test.
4. Strict mode (the default) fails the build on a call to a function the pack never defines;
   read the list it prints. `-Pra.strict=false` turns it into a warning for half-written work.

Read [Architecture](architecture.md) for the model (parts, the `Ra` registry, load and tick
order) and [Conventions](conventions.md) before writing Kotlin. [Kore Gotchas](gotchas.md) lists
the traps that already cost time.

## Naming conventions

Every identifier below is written into saved worlds. Renaming one orphans existing blocks, so
these are contracts, not style. Shared ones are constants in `ra/core/Ids.kt` (`Obj`, `Tag`,
`Storage`); module-private ones are `private const val`s in the module.

### Entity tags

- **Format:** `ra.{category}.{block_name}`
- Every entity the pack summons carries `ra`, so `/kill @e[tag=ra]` removes them all.
- `ra.custom_block` — every custom block marker; `ra.custom_block.<id>` — one type (`Tag.customBlock(id)`)
- `ra.multiblock` / `ra.multiblock.<id>` — multiblock markers (`Tag.multiblock(id)`)
- `ra.billboard`, `ra.display` — goggles billboards and display entities
- `ra.spawned`, `ra.place.<id>` — the bat a block item spawns (`Tag.place(id)`)
- `ra.new` — a marker placed this tick; `ra.broken` — break cleanup
- `ra.debug` — players who receive debug messages

### Player tags

- `ra.wrench_active`, `ra.cdh_active`, `ra.dh_active`, `ra.clip_active`, `ra.meter_active`,
  `ra.remote_active` — the tool is in use this tick
- `ra.<tool>_clicked` — click tracking, cleared each tick by `ra:tick`

### Scoreboards

- **Format:** `ra.{name}`, lowercase, dot-separated
- **Core:** `ra.temp` (fake players `#name`, never read across ticks), `ra.cooldown`
- **Orientation:** `ra.facing`, `ra.yaw`, `ra.pitch`
- **Redstone:**
  - aggregate `ra.power` (`0..16`); world-space `ra.power.up/down/north/south/east/west`;
    look-space `ra.power.front/back/left/right/local_up/local_down` (`detect_local` only)
  - `0` no power, `1..15` normal, `16` superpower (a repeater, comparator or observer driving the block)
  - pick the cheapest reader that answers the question: `RaLib.Redstone.any` or `detectSwitch`
    for on/off, `RaLib.Redstone.Local.*` for one face, `detect` only when every side matters.
    Cheaper still is a base block that carries the answer (`dispenser[triggered=true]`,
    `note_block[powered=true]`), though `triggered` also picks up quasi-connectivity.
  - new power sources go in the `#ra_lib:redstone/*` block tags (`lib/redstone/RedstoneTags.kt`),
    never in a per-direction copy of a test
- **Transport:** `ra.tr.net`, `ra.tr.cap`, `ra.tr.class`, `ra.tr.carry`
- **Multiblock:** `ra.multiblock`, `ra.mb_timer`, `ra.heat`
- **Inventory:** `ra.inv.count`
- **Settings:** `ra.set.tmp`; user settings `ra.u.snd`, `ra.u.par`, `ra.u.dbg`
- **Triggers:** `ra.wrench`, `ra.dh.action`, `ra.edit_type`, `ra.settings.open`, …

### Data storage

- **Format:** `ra:{name}` — `Storage.TEMP` (`ra:temp`), `Storage.MULTIBLOCK`, `Storage.TRANSPORT`,
  `Storage.SETTINGS`, `Storage.DH`, `Storage.CDH`, `Storage.WRENCH`, …

### Item custom data

- `custom_data={ra:{<id>:1b}}` — derived from `CustomBlock.id`, never typed by hand
- Tools: `{ra:{wrench:1b}}`, `{ra:{goggles:1b}}`, … (`tools/ToolItems.kt`)

### Marker data

- `data.properties.<key>` — configurable (wrench, Data Handlers)
- `data.data.<key>` — runtime state
- `data.status.<key>` — what the goggles read
- `data.type` — the block id, written by `ra_lib:placement/place`; the wrench and read-only
  registries are keyed by it
- multiblocks: `data.facing`, `data.inputs`, `data.outputs`, `data.controls`

### Function paths

- Block functions: `<namespace>:blocks/<dir>/<action>` (`block.fn("action")`)
- Item functions: `<namespace>:items/give_all`
- Tools: `ra:tools/<tool>/<action>`
- Library: `ra_lib:<sub-system>/<action>`, public ones referenced through `RaLib` in `ra/api/LibApi.kt`

The Kotlin file that writes a path mirrors it; [Project Reference](project-reference.md) maps
every namespace to its package.

## Settings, triggers and input

Adding a setting is one row on a page in `ra/settings/pages/`, never an edit to a shared
list. The generator in `ra/settings/gen/` writes the menu, the defaults, the per-player
seeding and the operator function tree from it ([Settings Internals](settings-internals.md)).

- **Scope decides how it is reached, not just who may change it.** `global`
  generates `/function ra_settings:admin/...` and never appears in the in-game
  menu. `user` appears only in the menu and needs a short, stable `obj` — a
  player's saved choice is found by objective name, so renaming one resets
  everybody.
- **Anything that alters game balance is `global`.** Anything that alters what one
  person sees or hears is `user`. A per-player EU cost would let one player mine
  cheaper than someone beside them.
- **Reads must fail open.** `ra_settings:get` requires a default; pass the value
  that keeps the feature working. A settings lookup must never be able to disable
  a module.
- **Block defaults apply at placement**, not live. Never put a settings lookup in
  `ra_lib:util/property`.
- **A setting that does nothing is worse than no setting.** If it cannot be wired,
  do not declare it.

### Triggers

- `/trigger` is the only control surface a player without permissions has. Every
  button a non-operator can press must **run** a trigger. Never `suggest_command`
  a `/function` at a player — it fills their chat box with something the game
  refuses.
- **Enable a trigger only where it is usable.** Enabled triggers appear in every
  player's `/trigger` completion whether or not they do anything: while the tool is
  held, while the menu is drawn, while the jetpack is worn. `scoreboard players
  reset` is what takes one back — the enabled flag lives with the score.
- **Prefer a spare code on an existing trigger to a new objective.**
- **Reserve code 1 for "show me the thing".** A bare `/trigger <obj>` adds 1, and
  that is somebody asking to see the menu, not to perform whichever action happens
  to be first in a list.

### Input

- Use `ra_lib:input` for typed values. Do not write a second input path.
- **Open the session after `ra_lib:input/tick` in the tick order.** A session
  opened before it is scanned in the tick it was created, which the book backend
  does not expect.
- **Check the request id before consuming.** The library is shared; `consume`
  tears the session down as it reads, so consuming another tool's answer hands it
  an empty result. Copy `ra.input.req` into a score of your own right after opening
  (`ra.settings.req`, `ra.dh.req`, `ra.remote.req`), and before polling,
  `execute unless score @s <tool>.req = @s ra.input.req` clears your pending flag
  and returns: your request was cancelled when the other one opened, so it is never
  coming back.
- **Keep what the question was per player.** The answer arrives ticks later, after
  other players may have asked their own. Store it keyed by your request id
  (`ra:settings edits.r<id>`, `ra:dh pend.r<id>`), never in one shared slot, and
  remove it on every path that stops the wait: applied, cancelled, expired,
  superseded, or replaced by a new question.
- **Re-check permissions when the answer arrives.** Whatever allowed the question
  (operator access, a field not being read-only) can have changed by then.

## New block checklist

Everything a block needs is in its own file plus one line in its module. The shared lists the
beet pack edited per block (placement handlers, goggles dispatch, `give_all`, bundles) are built
from the registry.

- [ ] One `object` per block in `modules/<module>/<Block>.kt`, holding its
      [`CustomBlock`](custom-blocks.md) — the id is final once worlds exist.
- [ ] `fun Ra.register<Block>()` calling:
    - [ ] `block(block)` — placement handler and goggles route
    - [ ] `pack.blockGive(block)`
    - [ ] `pack.blockRecipe(block, unlockedBy = Items.X) { pattern(...); key(...) }` — recipe and
          its unlock advancement
    - [ ] `pack.define(block.handlePlacement) { placementGuard(block); placeBlock(block); …; finishPlacement(block) }`
    - [ ] `pack.blockOnBreak(block) { cleanup }` and `pack.blockTick(block, onBreak) { … }`
    - [ ] `pack.define(block.goggles) { gogglesHeader(block); propLine(...) … }`
- [ ] If its vanilla block would fire its own inventory on a redstone edge (dispenser, dropper),
      use a barrel and `RaLib.Skin.apply` instead — see "Block Skins" in the
      [Developer Guide](developer-guide.md#block-skins).
- [ ] In the module object: call `register<Block>()`, add the block's `tick` to the module
      `tick`, its `give` to `items/give_all`, its item to the module's `GiveBundle`.
- [ ] `properties(block) { ... }` right after `block(block)`: every `data.properties` entry the
      block reads or writes, with its type (`number(min, max)`, `bool`, `text`, `item`,
      `list(of, max, pad)`) and flags (`readonly`, `adminOnly`, `visible`). Declaration order is
      the Data Handler's menu order. Declare `properties(block) {}` for a block with none. The
      build warns about any property name a block's functions use without declaring it, and
      about every `dynamic(...)` declaration. See
      [Property schemas](tools-and-registries.md#property-schemas).
- [ ] Wrench rows, if needed ([Tools and Registries](tools-and-registries.md)):
      `ra.wrenchCycle(...)`, `ra.wrenchToggles += TagRoute(...)`.
- [ ] Settings defaults, if any: a row on the module's page in `ra/settings/pages/`
      ([Settings Internals](settings-internals.md)).
- [ ] An advancement in `ra/advancements/` if the block belongs in the tab.
- [ ] The module's docs page: what it does, its recipe picture, its properties.
- [ ] `CHANGELOG.md` (`redstone_additions/CHANGELOG.md`) under the next version.

## Multiblock checklist

The full API is in [Multiblock Library](multiblock-library.md).

- [ ] Describe the structure once with `multiblockSpec(id, name, tier) { … }`, facing **north**,
      offsets relative to the base: `hint`, the blocks, and the named `inputs`, `outputs`,
      `controls` (`rotates = false` for a symmetric one). The library derives the other facings.
- [ ] Register it with `Ra.multiblock(spec)` from the part's `register()`.
- [ ] A `tick_dispatch` selecting `ra.multiblock.<id>`, hooked into `MultiblockLib.Hooks.TICK`.
      Reach IO blocks through `MultiblockLib.Io.at` / `isBlock` rather than branching on facing.
- [ ] Optional `on_break` hook (`MultiblockLib.Hooks.ON_BREAK`) for cleanup beyond removing the marker.
- [ ] Goggles: `ra.multiblockGoggles += TagRoute(Tag.multiblock(id), goggles)`.
- [ ] An advancement and the docs page, as for a block.

Assembly, rotation, periodic validation, disassembly and the marker tag come from the library.
Structure-specific `validate`, `check_structure` and `setup_type` hooks are only for shapes a
block list cannot express; none of the pack's structures needs them.

## Before opening a pull request

- [ ] `./gradlew koreBuild` passes in **strict** mode.
- [ ] For a refactor or anything meant not to change behaviour:
      `python3 tools/compare_reference.py --reference <pack folder> --all` against the previous
      build shows no differences, or the PR says why.
- [ ] Played in a world: `/reload` with no errors in the log; place, break and configure what
      you changed; goggles and wrench on it.
- [ ] No file over ~300 lines; Kotlin package mirrors the generated path ([Conventions](conventions.md)).
- [ ] Docs and changelog updated.

Releases follow [Release and Versioning](release.md).

## Block template

A block that does something each tick while powered. Replace `Example` and `example` with
yours, and `Ns.MYMODULE` with your module's entry in the `Ns` enum (`ra/core/Ns.kt`).

```kotlin
package ra.modules.mymodule

object Example {
	val block = CustomBlock(Ns.MYMODULE, "example", "Example Block", model = "minecraft:observer", dirType = 1)
	val process = block.fn("process")

	fun Ra.registerExample() {
		block(block)
		pack.blockGive(block)
		pack.blockRecipe(block, unlockedBy = Items.OBSERVER) {
			pattern("SRS", "SOS", "SSS")
			key("S", Items.STONE); key("R", Items.REDSTONE); key("O", Items.OBSERVER)
		}

		pack.define(block.handlePlacement) {
			placementGuard(block)
			placeBlock(block)
			data(newMarker(block)) { modify("data.properties.cooldown") { set(20) } }
			finishPlacement(block)
		}

		pack.define(process) {
			function(RaLib.Redstone.detectSwitch)
			// ... the block's behaviour, as the marker at the block
		}

		pack.define(block.goggles) {
			gogglesHeader(block)
			propLine("cooldown", "Cooldown: ", "aqua", y = 0.8, suffix = "t")
		}

		val onBreak = pack.blockOnBreak(block)
		pack.blockTick(block, onBreak) {
			execute { asTarget(markers(block)); at(self()); run { function(process) } }
		}
	}
}
```

[Extension Examples](extension-examples.md) builds a complete addon around this shape;
[Custom Blocks](custom-blocks.md) documents every helper used here.
