# Kore Rewrite

Redstone Additions is being rewritten from hand-written `.mcfunction` / JSON files built by
[beet](https://github.com/mcbeet/beet) to Kotlin, generated by [Kore](https://kore.ayfri.com).
This section documents the rewrite: how the new project is laid out, how to build it, and the
rules that keep it maintainable.

The gameplay documentation (modules, tools, settings) still applies unchanged — the rewrite
changes how the pack is **written**, not what it **does**.

## Why Kore

The beet pack is ~1,400 files and ~19,000 lines of mcfunction. Most of its bugs were one of
two kinds, both documented at length in the old Developer Guide:

- **The same fact typed in many places.** A block's identity was retyped in its give
  command, recipe, drop, bundle, placement tag, marker tag, goggles dispatch, `give_all` and
  unlock advancement. "ID mismatch between recipe result and placement handler tag" headed
  the list of common failures.
- **Calls nothing checks.** `function ra_lib:redstone/detct` loads fine and does nothing; the
  only signal is a line in the game log after `/reload`.

In Kotlin both become compile-time questions. A block is one `CustomBlock` value and every
place that needs its id derives it. A function is one `FunctionArgument` value used for both
its definition and its calls, and the build fails on a call to a function nobody defines.

## What stays the same

The rewrite keeps the pack's **runtime contract** byte for byte, so existing worlds keep
working and no player-facing command changes:

- every namespace (`ra`, `ra_lib`, `ra_gates`, …) and every function path;
- every entity tag, scoreboard objective and data storage;
- every item's components (`custom_data={ra:{<id>:1b}}`, the bat spawn egg shape);
- the tick order of modules.

## What changes

| | beet | Kore |
|---|---|---|
| Source | `redstone_additions/src/**/*.mcfunction`, `*.json` | `redstone_additions_kore/src/main/kotlin/ra/**/*.kt` |
| Build | `beet build` (Python) | `./gradlew koreBuild` (JDK 25) |
| Minecraft versions | 1.21.9 – 26.3 via overlays | **26.3 only** (pack format 121) |
| 26.3 port | `tools/port_26_3.py` rewrote shapes at build time | Not needed: Kore writes 26.3 shapes |
| Macro lint | `tools/lint_macros.py` | Typed macro arguments + `PackValidator` |
| Settings menu | `tools/settings/*.json` + `settings_gen.py` | Kotlin data in `ra.settings` |
| Shared lists (placement handlers, goggles dispatch, give bundles, wrench registry…) | Hand-edited per block | Built from the `Ra` registry |

Supporting older Minecraft versions was dropped deliberately: Kore checks its output against
exactly one game version, and the overlays plus `port_26_3.py` existed only to bridge shapes
that changed inside the old range.

## Status

The port proceeds part by part (see [Architecture](architecture.md#parts)). A part is done
when `tools/compare_reference.py <namespace>` reports no unexplained difference against the
last beet build and it has been played in game.

| Part | Namespace | Status |
|---|---|---|
| Foundation (`ra.core`, `ra.api`) | — | Done |
| Logic Gates | `ra_gates` | Clock ported as the reference example |
| Everything else | — | In progress |
