# Redstone Additions: ideas for v6.0.3

## Known issues carried over from the v6.0.2 review

- **Medium — oversized network rebuild retries forever.** One loaded network over ~1500 nodes can
  never fit a rebuild in the 65536-command limit; since 6.0.2 the cut-recovery retries it every
  5 ticks, and each cut also skips the rest of `ra:tick`. Count consecutive cuts and stop (tell
  admins) after 2–3; run the rebuild as its own top-level tick entry; cap net-0 intake.
  (`Transport.kt` ~L65, `Rebuild.kt` ~L50, `Scope.kt` full_batch)
- **Low–medium — ender partner search is O(receivers) per pick.** `ra_ender:link/pick` visits every
  receiver with no limit; total cost grows with vaults². Index receivers by channel (score/tag) and
  select with `limit=1,sort=nearest`. (`Link.kt` ~L156)
- **Low — Tag Adder/Remover re-check every entry on every pulse** (~15 commands per character).
  Cache the checked list on the marker like `ra_lib:safe/guard` does. (`ra_sensors:tags/load`)
- **Cosmetic — a poured potion can show default blue** when the take emptied its record (colour
  read after the take). Read the colour first. (`drain_potion`)


Backlog of new blocks, modules and library work planned for **v6.0.3**. Written against v6.0.1
(and early 6.0.2) docs and sources; nothing here is implemented yet. Pick items from the top-10 at
the end, file an issue per item, and work on them on their own branches.

The 26.3 feature notes come from minecode `get_technical_changes 26.1 → 26.3`, which worked.
Anything marked **(verify)** is my own reading of a changelog line, and I have not yet checked
it against the 26.3 schema with spyglass or misode.

Legend: **Diff** S = a day or less, M = a few days, L = a week or more. **Value** low / med / high.
"Shell" means the existing output convention: iron blocks in the 3×3×3 cube turn into redstone blocks.

**Design rules to respect** (from conventions / architecture / gotchas), referenced below as R1–R8:

- **R1**: no per-tick cost while idle. Pipes and wires do no work per tick. Machines pace themselves with `ra.cooldown`.
- **R2**: player text goes through `ra_lib:safe` formats before it reaches any macro. Selectors and tags are admin-only unless the `adminSetting` allows them.
- **R3**: every setting is declared in a property schema. No dynamic props.
- **R4**: identifiers are a compatibility contract. Renames and repairs need a step in `ra/migrations`.
- **R5**: arithmetic with more than one step is one `/compute` via `core/Compute.kt`.
- **R6**: per-player settings (sounds, particles) filter what a block emits. Server settings set the defaults.
- **R7**: files stay under ~300 lines, and the Kotlin path mirrors the generated path.
- **R8**: parts never edit each other's files. They register, and the owning part builds the output.
